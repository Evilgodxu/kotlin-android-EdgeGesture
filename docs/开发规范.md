## 1. 注释规范

KDoc / Javadoc 只写两类内容：

- **API 契约**：类/接口说明分层角色与生命周期归属；方法说明参数、返回值、空可性（`@Nullable` / `@NonNull`）、线程约束（`@MainThread` / `@WorkerThread` / `@AnyThread`）、是否有异步或副作用。
- **关键实现**：只写读代码看不出的隐性约束——状态机流转、锁与并发、Bundle/Intent 序列化边界、回调时序、生命周期敏感点。

不写来源追溯（"参考 XX 源码""对齐 XX 分支"）和与代码无关的需求背景、排期、责任人。

## 2. 版本与 API 核实

依赖坐标、版本目录、AGP/Gradle/Kotlin/JDK、SDK 层级、AndroidX 与 Jetpack（含 Compose BOM）、任何平台或框架 API，一律查官方一手来源后再写代码，禁止凭记忆输出已废弃或已移除的接口。

- **版本类**：AGP↔Gradle↔JDK↔NDK 兼容矩阵以 AGP Release Notes 为准；`compileSdk` / `targetSdk` / `minSdk` 叠加 Google Play target API 门槛；Compose 库版本走 BOM 映射表，Compiler 跟随 Kotlin 而非 BOM。
- **API 类**：确认引入的 API level 与行为变更；区分 Stable / Experimental（需 `OptIn`）/ Deprecated（按 `ReplaceWith` 给迁移路径）/ Removed 四态；AGP 10 起改用 `androidComponents {}` 替代已移除的 `BaseVariant` 与直接 Task 访问；Compose 签名以 Release Notes 为准。
- **执行**：查不到就标"版本待核实" + 查证路径，不做确定断言；版本统一收敛到版本目录，平台差异用 `Build.VERSION.SDK_INT` 分支并附文档链接；禁止沿用旧版本旧写法而不提示迁移。

## 3. Android 构建验证质量门禁

### 3.1 缺陷零容忍

CI 门禁（Gradle 编译 + Lint + 单测）发现存量代码的编译错误、Lint Error 或崩溃缺陷，必须立即修复至绿灯。禁止以 Known Issue、抑制告警等方式让红灯过闸、带病提测或发版。

### 3.2 弃用 API 强制迁移

扫描到 `@Deprecated` API（旧 Support 库、废弃 Framework / Jetpack 接口），必须重构迁移至官方等价实现（AndroidX / 新 Jetpack / 新 Platform API）。禁止 `@SuppressWarnings("deprecation")`、关闭 `lintOptions` 或新增 lint-baseline 压后处理，须源头清零 Deprecation 告警，避免技术债累积。

### 3.3 实验性 API 禁用

禁止调用实验性 API（`@RequiresOptIn` 类注解，如 Compose `@ExperimentalMaterial3Api`、AOSP `@FlaggedApi`）。仅当无稳定版等价实现时可例外，须评审留痕：锁定依赖版本、登记豁免清单、明确 Owner 与迁移计划。

获批豁免外，禁止用 `@OptIn`、`@Suppress("OPT_IN_USAGE")` 或全局 `-opt-in=` 静默 opt-in 警告，不得放宽 `UnsafeOptInUsageError` 级别或塞入 baseline。

### 3.4 判定优先级

编译/崩溃错误 > Deprecation > 实验性 API，任一未清零即红灯阻断。

### 3.5 落地要点

- `abortOnError true`，Deprecation 与 UnsafeOptIn 提级为 Error。
- baseline 只减不增。
- 豁免项用窄范围 `@OptIn`，禁止全局。
- AOSP / ROM 场景将 Gradle / Lint 替换为 Soong / Make + CTS / VTS。

## 4. Compose 状态提升

- 状态至少提升到所有读取它的组合项的最低共同父项。
- 状态至少提升到可以写入它的最高层级。
- 同一事件触发的多个状态变更，应一起提升。

## 5. Compose 性能与重组

- 用 `remember` 缓存昂贵计算（更好的是把计算移出组合项，放 ViewModel）。
- `LazyColumn` / `LazyRow` 用 `key` 提供稳定唯一键（不能用 `hashCode`）。
- 状态快速变化时用 `derivedStateOf` 限制重组范围。
- 推迟状态读取：把状态读取包在 lambda 里。
- 频繁变化的状态用 lambda 版修饰符（如 `Modifier.offset { }`），让读取发生在布局/绘制阶段而非组合阶段。
- 禁止向后写入：绝不写入本组合项中已被读取过的状态。

## 6. Compose 稳定性

- 稳定参数 → Compose 可跳过重组；不稳定参数 → 父级重组时必然重组。
- 传给组合项的数据类用 `val`，`var` 会让类变成 unstable。
- 按需用 `@Immutable` / `@Stable` 标注，或用 kotlinx immutable collections。

## 7. 协程与线程

新增或修改既有代码时，耗时任务（IO、数据库、图片解码、计算密集操作等）应基于 Kotlin 协程 + 结构化并发，结合 `viewModelScope` / `lifecycleScope`，通过 `withContext(Dispatchers.IO / Dispatchers.Default)` 切离主线程；性能基线默认按低端机 / 受限设备预设，但底线仅是主线程不阻塞、无 jank / 不掉帧（守住对应刷新率的帧预算）。在此约束下，可并行任务应充分使用多线程 / 协程并发提升吞吐，避免过度串行化。

## 8. 架构与依赖注入

- 依赖注入统一通过 Koin 框架实现，禁止手动创建或管理依赖实例。
- 新增或修改既有代码时，必须遵循单向数据流（UDF）架构，禁止引入非 UDF 的实现方式。UDF 即"状态向下、事件向上"，无状态组合项更好复用、易测试；Screen 级状态提升到 ViewModel，组合项只接收不可变状态和事件 lambda。

## 9. 目录命名与组织规则

- **父目录按大类型命名**（`ui` / `screens` / `data` / `component`），子目录按语义命名（`player` / `title` / `playlist`）。
- **禁止把类文件平铺到父目录下**：父目录下只应出现语义化子目录，不直接放业务类文件。
- **单一职责**：一个文件、一个目录只承担一类职责；纯展示的布局组件不写单元测试。

## 11. Activity 边界与状态归属

- **Activity 只做入口**：仅负责 `setContent` 挂载导航图、全局副作用与跨形态分发；不持有任何状态字段，不做数据加工，不成为数据源。
- **禁止 override 生命周期回调处理业务**：不用 `onResume` / `onStop` 跑 UI 或数据逻辑，改用 `LifecycleStartEffect`、`LifecycleResumeEffect`、`repeatOnLifecycle`、`collectAsStateWithLifecycle`。
- **Screen 级状态 → ViewModel**：跨配置变更存活、绑定目的地生命周期、访问数据层并产出 UI state，属强推荐。
- **UI element state 就近持有**：输入文本、展开态、滚动位置、Dialog 可见性等用 `remember` / `rememberSaveable` 或 plain state holder，不下沉到 ViewModel。
- **可复用组件禁止持有 ViewModel**：同一 `ViewModelStoreOwner` 下会拿到同一实例，改用 plain state holder。
- 原则：状态放在离消费处最近的位置，只在更高层确实需要时上提。

## 12. 页面模块结构

标准页面（以 `home` 为目标形态）：

```
screens/home/
├── component/                # 页面共享组件单元（按语义命名子目录）
│   ├── player/               #   播放区单元
│   ├── title/                #   标题区单元
│   └── playlist/             #   列表区单元
├── compact/CompactAssembly.kt      # 窄屏组装器
├── expanded/ExpandedAssembly.kt    # 宽屏组装器
├── dialog/                   # 页面弹窗
├── HomeScreen.kt             # 页面入口：形态分发 + 跨形态副作用
├── HomeUiState.kt            # 页面级 UI 状态（全局唯一）
└── HomeViewModel.kt          # 页面级 ViewModel（全局唯一）
```

- 页面级 `UiState` 与 `ViewModel` 各唯一，不随形态分裂。
- `component/` 只放页面内共享的组件单元，按语义拆子目录，不平铺文件。

## 13. 组装器与自适应布局（强约束）

```
{Xxx}Screen                  只做形态分发与跨形态副作用，不含布局
├── compact/CompactAssembly.kt      窄屏组装器（独立文件）
└── expanded/ExpandedAssembly.kt    宽屏组装器（独立文件）
```

- **原子化拆分**：布局组件最小单元化；被多处复用则共享上浮（到 `ui/` 或页面 `component/`），仅单处使用则私有下沉。
- **由组装器组装**：`CompactAssembly` / `ExpandedAssembly` 各自组装所需展示内容，`Screen` 本身不写布局。
- **窗口尺寸类分发**：显示内容按窗口尺寸类分派到对应组装器，**禁止 if 布局**；最佳实践是由屏幕旋转状态与窗口尺寸类共同控制显示内容。

## 14. 测试策略

### 14.1 定位：与真机测试互补，不互相替代

真机验证不可被替代：真实渲染、手势体感、帧率与发热、系统交互（通知、悬浮窗、媒体会话）。单元测试不可替代真机；但它覆盖真机难以稳定触达的部分，二者按金字塔配比共存，官方建议 **70% 单测 / 20% 集成 / 10% 端到端**。

### 14.2 单测相对"装到设备上手测"的独占价值

- **可穷举分支**：错误分支、超时重试、并发竞态、空列表、边界值、配置变更与进程死亡恢复，手测要么难以构造、要么复现不稳定。
- **可锁定回归**：每个已修缺陷固化成一条用例，重构时立刻暴露回退；手测的结论是一次性的，不沉淀。
- **反馈成本**：JVM 秒级 vs 编译安装分钟级，因此能进入每次提交的 CI 门禁（见第 3 章），红灯阻断。
- **确定性**：`runTest` 虚拟时间 + `StandardTestDispatcher` 精确控制异步时序，不依赖 `Thread.sleep` 与真机调度。
- **可定位**：小测试单类验证，失败即定位到具体函数；大范围手测失败需二次二分。

### 14.3 必测项（下限）

- ViewModel 单测：含 Flow / StateFlow 的状态流转（loading / success / error）。
- 数据层单测：Repository、DataSource、DTO 与实体映射。
- 关键用户流 UI 测试：导航与核心路径，作为 CI 回归门禁。
- **不测纯布局**：无逻辑的展示型组合项不写单测（见第 9 章单一职责）。

### 14.4 写法约束

- 依赖经构造注入（Koin），测试直接传入 test double。
- **Fake 优先于 Mock**：Fake 校验行为结果，Mock 易退化成校验调用序列；仅在确无等价 Fake 时用 Mock。
- StateFlow 断言 `.value`，不断言中间合并值；需按序校验发射时用 Turbine。
- 协程测试用 `runTest` + `StandardTestDispatcher`（需断言中间态则配合 `advanceUntilIdle()`），`Dispatchers.setMain` 必须配对 `resetMain`。
- 测试目录镜像生产结构，一个类一个测试类；用例名描述行为而非实现。
- 失败即修复，禁止 `@Ignore`、禁用用例或放宽断言让红灯过闸。
